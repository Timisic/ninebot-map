# 采集、地图与发布

九号项目有三类运行位置。

| 位置 | 工作 | 数据 |
| --- | --- | --- |
| 本机 CLI | 登录、手动采集、下载档案、打开交互地图 | `.private/` 和 `data/` |
| 独立私有 GitHub 仓库 | Actions 定期采集，持久保存加密档案 | `state` 分支的 `state.enc` |
| 用户指定的公开仓库 | 展示持续更新的无底图轨迹图片 | PNG 和 README 图片块 |

`./run cloud install` 配置私有同步仓库。默认连续间隔为 10 天，每小时检查到期时间。采集成功更新成功时钟；图片发布重试保留该时钟。`./run cloud status` 查看工作流、采集与图片发布状态。

`./run cloud map` 下载、合并档案并打开本地地图。`./run cloud pull` 只下载并更新标准数据。已经打开的地图跟随有效数据更新，保留筛选与地点名称。本机下载由显式命令触发，云端调度无需本机运行。

源码部署是独立操作。`cloud install` 将代码和文档复制到私有仓库，现有加密历史沿用原 `state` 分支。修改部署复制清单时，用云端合成测试验证文档移动后的打包结果。

公开代码包含程序、项目技能、文档、合成 fixture 和已授权的轨迹 PNG。原始坐标 JSON、会话、密钥和私人证据留在 Git 忽略目录中。公共源码同步与云端图片更新是两个不同的发布操作。

常规验证使用 `npm run verify`，运行数据来自合成 fixture。真实 `cloud status`、`cloud pull`、`cloud map` 与强制采集由具体任务的授权决定，不能把合成验收说成真实云端采集验收。
