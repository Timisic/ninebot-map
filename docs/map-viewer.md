# 在本机查看骑行地图

先运行 `./scripts/setup.sh`。查看地图不需要登录，也不会读取账号目录。

```bash
./run map
./run map --dataset /path/to/dataset.json
./run map --latest
./run map --dataset tests/fixtures/synthetic-map.json --no-open
```

不带 `--dataset` 时打开导入页。点击顶部“导入”或拖入 Ride Dataset v1 JSON 文件。指定 `--port 0` 可自动选择空闲端口；终端会显示实际地址。按 Ctrl-C 关闭服务。

`--latest` 读取已选车辆的本地最新标准数据。指定数据文件后，运行中的服务保留上次有效数据，并在文件更新时重新校验；原来的生成目录路径也会跟随 `prepared/latest.json`。页面每分钟及回到前台时检查更新，保留日期范围、坐标解释、已保存地点名称和视图。手动导入后停止跟随后台数据，重新打开页面可恢复。升级前已经启动的服务需要重启一次。

全历史统计来自文件中的全部行程。地图只显示数据集允许的采样轨迹，日期筛选按数据集声明的时区包含起止两天。日期筛选不会扩大数据集原有地图范围，也不会改动全部历史统计。无匹配轨迹时会显示空状态。

顶部主题按钮可切换深色与浅色，默认深色。选择保存在此浏览器；无法使用浏览器存储时，仅本次页面有效。地图滚轮围绕指针位置缩放，连续的一段输入最多改变一级，停止后可再次缩放。在线底图的最大缩放以可用瓦片为限。

## 路线、经过与终点

路线按行程独立绘制，Canvas 使用 `lighter` 混合。相同位置的多条路线叠加会变亮。浅色模式为路线增加深色衬线，浅色下底图保持 OpenStreetMap 原色，深色下仅在本机调整瓦片颜色，不增加模糊滤镜；地图采用整数缩放，并开启高像素密度瓦片支持。相邻采样点相距超过 1,000 米时断开绘制，也不统计中间区域。孤立点仍可显示，但不构造补充路线。

“经过次数”使用约 200 米的方格，统计当前日期内有多少次不同的行程经过。每次行程在一个格子里只计一次，重复采样、来回经过和环线不会增加该格子的次数。线段穿过的格子也会计入，与点密度无关。鼠标移到区域或轻点地图可查看次数。

“常去地点”只取每条轨迹的最后一个观测点，不推断停留、地址、家或工作地。先用全部地图轨迹建立固定分组，再按日期取成员交集。因此筛选日期不会移动分组或重新命名。列表按当前结束次数排序，显示最多前 100 处；地图默认只标出前六处，选择其他地点时显示对应标记。列表与地图标记共享顺序。地点列表默认收起，展开为 256 像素宽的浮层；地图针图形为 16 像素，透明点击区域为 44 × 44 像素。点击地图针可展开列表，选择地点可突出相关路线，并编辑本地名称。

名称存于此浏览器的 localStorage，以数据集标识、坐标解释和聚类设置隔离。名称关联标注时的行程成员，不关联排名。新增数据改变锚点时，通过原成员恢复名称；多个不同名称并入同组时不自动猜测，旧名称仍在本机保留。浏览器禁用存储时，本次页面仍可编辑名称，关闭后失效。导入其他文件不会向服务端写入名称。

## 坐标与底图

默认不加载任何网络地图。数据中声明 `unverified` 的坐标以原始值进行相对预览，网格与距离聚类仅为近似。界面保留这项说明。

“设置”提供道路底图与坐标系选项；展开其中的“数据与隐私”可查看坐标、统计和网络请求说明。可手动选择原始 WGS84 预览，或用本地 gcoord 将 GCJ-02、BD-09 校准到 WGS84 后叠加 OpenStreetMap。原始文件保持不变。手动选择不等于核实了数据来源坐标系，转换也存在近似误差。北京等中国大陆地区也应对照道路选择，不能仅凭城市名称判断坐标系。

可在本地页面地址后添加 `#title=北京骑行地图&crs=wgs84&basemap=osm`，以指定标题和手动坐标预览并开启底图。这个设置只影响页面，不修改数据。

开启在线底图会向 OpenStreetMap 请求当前视野的图片，服务方可据此知道大致区域。数据文件、路线点和本地名称不会上传。底图失败不影响路线。没有自动定位、反向地理编码、分析上报、远程字体或瓦片批量下载。

## 计算约定与限制

网格采用球体半径 6,371,008.8 米的局部等距近似，经度比例固定为数据范围中心纬度的余弦。投影原点固定在全部地图点包围盒中心，日期筛选不改变网格。仅接受经纬跨度分别不超过 3°、纬度在 ±75° 内的数据；跨区域与跨日期变更线数据需要预先拆分。网格不是精确道路匹配。

每个格子包含左侧和下侧边界。恰好经过角点的线段只增加前后两个内部格子，不额外计入侧边格子；线段的两个端点各计入其所属格子。重复零长度点安全。

终点分组先计算每个终点 100 米半径内的全部终点数。这个密度只计算一次，按密度从大到小、行程 ID 从小到大排序。依次将尚未分组的终点作为固定锚点，吸收半径内未分组的终点。不移动中心，不做链式合并。每个终点恰好属于一组，单个孤立终点也保留。

输入上限为 40 MB、25,000 次行程、300,000 个轨迹点、1,200 个月份。空间计算还限制 1,500,000 个行程与网格关联、4,000,000 次空间分桶与边缘点比较。超过时明确报错，保留上一份有效地图。极度密集的大文件可能在达到文件上限前触及计算上限。

服务仅绑定 `127.0.0.1`，使用固定资源白名单和启动时读取的单份数据快照，不提供目录浏览。输入必须通过统计与关联验证，浏览器还会验证空间边界。服务拒绝异常 Host、跨站 Origin、跨站浏览器请求和写入方法。

## 开发验证

```bash
.venv/bin/python -m unittest discover -s tests -q
npm ci
npm test
npm run test:browser
npm run test:wheel
```

浏览器验证默认使用本机安装的 Chrome。可设置 `PLAYWRIGHT_CHANNEL` 选择 Playwright 支持的其他已安装浏览器通道。脚本启动独立随机端口服务，只使用合成 fixture，验证桌面、小屏幕、筛选、名称持久化、无效导入、底图门禁和默认无外部网络请求。它还对 Canvas 像素检测重叠增亮，对实际颜色检测文字对比度。`npm run test:wheel` 使用合成数据检查连续滚轮输入、输入方向变化、缩放边界与视图切换后的缩放行为。设置 `MAP_SCREENSHOTS=/local/output/path` 可保存合成截图。
